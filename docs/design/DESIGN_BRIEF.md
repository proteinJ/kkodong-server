## 1. 제품 한 줄

**꼬동** — "**꼬**순내 나는 **동**네". 우리 강아지의 **친구를 만들어주는** 동네 반려견 앱.

친구가 되는 주체는 **견주가 아니라 강아지**다. 이 한 문장이 모든 화면의 정보 위계를
결정한다. 견주는 강아지 뒤에 선다.

## 2. 아트 디렉션

**절충** — 구조는 미니멀, 색과 아이콘만 따뜻하게. 당근마켓 계열의 톤이다.
"프리미엄 반려동물 앱"으로 가면 이름과 어긋나고, "손그림 동네 앱"으로 가면
자칫 아마추어해 보인다.

### 2.1 컬러

| 토큰 | 값 | 용도 |
|---|---|---|
| `bg` | `oklch(93% 0.005 70)` | 화면 배경. 순백이 아닌 따뜻한 오프화이트 |
| `surface` | `oklch(97% 0.012 75)` | 카드 배경(크림) |
| `text` | `oklch(20% 0.01 60)` | 본문. 웜 블랙, `#000` 금지 |
| `text-muted` | `oklch(52% 0.01 60)` | 견종·나이 등 보조 정보 |
| `accent` | `oklch(56% 0.09 175)` ≈ `#3d7a6d` | 액션 버튼, 강조. 차분한 청록 |
| `accent-bg` | `oklch(94% 0.03 175)` | 이유 문장 배지 배경 |

**포인트 색은 하나뿐이다.** 강아지 누끼 사진이 화면에서 가장 화려한 요소여야 하므로,
UI가 색을 더 쓰면 주인공을 이긴다.

### 2.2 형태

- **8pt 그리드.** 모든 간격은 8 또는 4의 배수
- **라운드 12** (카드·버튼), 이미지 컨테이너는 16
- **그림자 대신 배경 대비**로 레이어를 만든다. 그림자를 쓰면 크림 배경이 탁해진다
- 타이포는 **SF Pro / Apple SD Gothic Neo**. 크기 4단계, 굵기 2단계를 넘지 않는다
- 아이콘은 **SF Symbols 기본**, 단 배변·발자국·강아지 관련만 커스텀 손그림

### 2.3 절대 금지

1. **AI 보라색 그라디언트, 글래스모피즘, 다크 메시 히어로** — 기본값 회피
2. **퍼센트·별점·게이지·매칭 점수** — 아래 3.2 참조
3. **지도** — Phase 2로 연기됐다. 지도 UI를 그리면 안 된다
4. **체급·에너지·견종 필터 칩** — 아래 3.3 참조

## 3. 꼬동 고유 규칙 (일반 앱 관행과 충돌하는 지점)

### 3.1 카드의 주인공은 강아지 누끼다

온보딩에서 촬영한 사진을 iOS Vision(`VNGenerateForegroundInstanceMaskRequest`)으로
배경 제거한 **누끼 PNG**가 프로필·추천 카드·산책 카드를 관통하는 브랜드 자산이다
(CONCEPT 3.5).

- 누끼는 **사각 크롭 없이** 배경 위에 그대로 떠 있다. 원형 아바타로 가두지 않는다
- 견주는 `displayName` 텍스트 한 줄. **견주 사진 필드는 API에 아예 없다**
- 누끼가 아직 없는 강아지는 `profileImageUrl`로 폴백 — 이 상태도 디자인해야 한다

### 3.2 숫자로 궁합을 말하지 않는다

> "궁합 87% 같은 표기는 근거 없는 정밀도를 주장하는 셈이고,
> 나중에 알고리즘을 바꾸기도 어려워진다" — CONCEPT 2.2

서버는 **점수를 응답에 넣지 않는다**(API_SPEC 규약 4). 대신 이유 문장을 내려준다:

> *"저녁에 산책하는 것도 같아요, 둘 다 활발한 성격이에요"*

이 문장이 **카드에서 두 번째로 큰 요소**다(첫째는 누끼). 거리를 제외한 신호 중 상위
2개로 조합되므로 길이는 대략 20~40자. 2줄까지 수용하는 레이아웃이어야 한다.

### 3.3 필터 UI를 두지 않는다

서버는 **반경만 조건이고 나머지는 전부 가중치**다(API_SPEC 규약 1). 성격이 안 맞아도
후보에서 사라지지 않고 순위만 내려간다. v2에서 매칭 알고리즘이 HOLD됐던 원인이
"조건을 AND로 걸면 유효 후보군이 사라진다"였고, v3는 이걸 구조로 풀었다.

**UI에 체급/에너지/견종 필터 칩을 두면 서버가 푼 문제를 클라이언트가 되돌린다.**
정렬 옵션도 마찬가지다. 추천 순서는 서버가 정한다.

### 3.4 빈 화면이 예외가 아니라 기본값이다

콜드스타트 상태에서 카드가 0~3장이다. **초기 사용자 대부분이 보게 될 화면**이므로
1급 시민으로 디자인한다.

서버는 결과가 `limit` 미만이면 반경을 **1→2→3→5km로 자동 확장**해 재조회하고,
확정된 반경을 응답(`appliedRadiusKm`)에 담는다. 즉 세 가지 상태가 있다:

| 상태 | 화면 |
|---|---|
| 정상 | 카드 리스트 |
| 반경 확장됨 | "5km까지 넓혀서 찾았어요" 같은 상단 안내 + 카드 |
| 후보 0 | 빈 상태. **"주변에 아무도 없어요"는 최악의 첫인상**(CONCEPT 2.2) — 다음 행동을 제시한다 |

### 3.5 상대 위치를 노출하지 않는다

거리는 **정수 km로 반올림**된 값만 내려온다(`distanceKm: 2`). 좌표·주소·동 이름은
응답에 없다. 지도 핀, "○○동 사는 몽이" 같은 표현 전부 불가.

### 3.6 친구 탭이 첫 화면이다

> "정보구조가 그대로 말하게 한다" — TICKETS FOUNDATION-2

탭 순서: **친구** / 산책 / 커뮤니티 / 채팅 / 마이. 산책 앱처럼 보이면 실패다.
산책·커뮤니티·채팅은 서버 미구현이므로 탭바에 자리만 잡고 내용은 비운다.

## 4. 그릴 화면

### 4.1 온보딩 (4단계)

| # | 화면 | 내용 |
|---|---|---|
| 1 | 안전 고지 | 만남 안전 수칙 + 포지셔닝 카피. 동의 후 진행 |
| 2 | 견주 정보 | 닉네임 · 자택 위치(지도 아닌 검색) · 산책 시간대(6개 중 최대 3개) |
| 3 | 반려견 등록 | 이름 · 견종 · 생년월일 · 체급 · 성향 태그(8개 중 최대 3개) |
| 4 | 누끼 촬영 | 사진 촬영 → 배경 제거 결과 확인 → 저장 |

**선택지는 전부 서버가 내려준다** — `GET /meta`가 견종 94종(7그룹) · 성향 8종 ·
시간대 6종과 각각의 `maxSelectable`을 준다. 견종은 자유 입력이 아니라 **그룹별 피커**다.

⚠️ **자택 위치는 필수다.** 없으면 추천을 받지도, 후보가 되지도 못한다(API_SPEC 규약 8).
나머지(생일·체급·성향·시간대)는 **전부 건너뛸 수 있고, 건너뛰어도 불이익이 없다** —
미입력은 0점이 아니라 중립 0.5로 처리된다(규약 6). 건너뛰기 버튼을 숨기지 말 것.

### 4.2 친구 탭 — 추천 피드 ★ 핵심 화면

3.4의 세 상태를 모두 그린다.

**카드 1장의 요소**(순서 = 시각적 위계):

```
① 강아지 누끼            ← 가장 큼
② 이름                   name
③ 견종 · 나이 · 체급     breed / ageMonths / size   (한 줄, muted)
④ 이유 문장              reason                     ← 두 번째로 큼, accent-bg 배지
⑤ 거리                   distanceKm  "1.2km"
⑥ 친구 신청 버튼         requestStatus 에 따라 상태 변화
```

`requestStatus`는 `none` / `pending` / (수락됨) 세 가지. 버튼 라벨과 활성 상태가 바뀐다.

**세로 스크롤 리스트**다. 틴더식 스와이프 덱이 아니다 — 커서 페이지네이션(`limit=20`)
구조이고, 카드를 넘겨 버리는 인터랙션은 "순위만 내려간다"는 설계 철학과 어긋난다.

### 4.3 강아지 상세

추천 카드를 눌렀을 때. 같은 응답의 필드를 펼친다 —
성향 태그 전체, 에너지 레벨, 이유 문장, 친구 신청 CTA.

### 4.4 마이 — 반려견 프로필 / 수정

등록된 강아지 카드 + 수정 진입. 온보딩 3·4단계와 폼을 공유한다.

### 4.5 (계약만 존재, 변할 수 있음)

받은 신청 · 보낸 신청 · 친구 목록. `FriendRequest` 엔티티가 아직 없어
`requestStatus`가 `"none"` 고정이다. 껍데기만 그린다.

## 5. 실제 API 응답 (화면 요소의 유일한 근거)

`GET /api/v1/friends/recommendations?dogId={myDogId}&limit=20&cursor=`

```json
{
  "dog": {
    "id": "...", "name": "몽이", "breed": "포메라니안",
    "ageMonths": 26, "size": "small", "energyLevel": "high",
    "personalityTraits": ["활발함", "사교적"],
    "cutoutImageUrl": "https://...", "profileImageUrl": "https://..."
  },
  "owner": { "id": "...", "displayName": "..." },
  "distanceKm": 2,
  "reason": "저녁에 산책하는 것도 같아요, 둘 다 활발한 성격이에요",
  "requestStatus": "none"
}
```

**여기 없는 값은 화면에 그릴 수 없다.** 상호 친구 수, 마지막 접속, 온라인 표시,
매칭 점수, 좌표 — 전부 존재하지 않는다.

성향 태그 8종: 활발함 / 차분함 / 사교적 / 낯가림 / 겁많음 / 장난꾸러기 / 독립적 / 애교많음
체급 3종: `small` / `medium` / `large`

## 6. iOS 구현 제약

- **Safe area** 준수. 탭바 위 콘텐츠가 잘리지 않게
- **터치 타겟 44pt** 이상
- **썸존** — 주요 액션(친구 신청)은 화면 하단 1/3
- **Dynamic Type** 대응. 한글은 영문보다 크게 잡히므로 카드 높이를 고정하지 말 것
- **다크 모드** — 크림 배경 앱이라 단순 반전이 안 된다. 웜 다크(`oklch(20% 0.01 60)`
  계열 배경 + 누끼는 그대로)로 별도 정의가 필요하다
