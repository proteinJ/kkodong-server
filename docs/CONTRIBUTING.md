# 팀 작업 규칙

3인(+ 각자의 Claude)이 같은 레포를 만진다. 이 문서는 **서로의 작업을 안 깨뜨리기 위한
최소 규칙**이다. 길게 읽을 필요 없이 「내가 뭘 하면 남이 안 막히나」만 담았다.

작업 전 이 문서와 [`STATUS.md`](STATUS.md)를 먼저 본다.

---

## 1. 누가 무엇을 맡나

| 사람 | 영역 | 티켓 접두어 |
|---|---|---|
| **proteinJ** | 견주 앱(iOS) 프론트 전체 + Phase 1 서버 | `FOUNDATION` `ONBOARD` `FRIEND` `CHAT` `WALK` `CARD` `COMMUNITY` `PET` `SAFETY` `MEET` `PASS` |
| **sechanjang** | 점주 앱(꼬동 파트너) 서버 + 프론트 | `PN-*` |
| **2-changmin** | 견주 앱의 지도·유치원 **서버** | `MAP-*` `KG-*` |

**견주 앱의 화면은 전부 proteinJ가 만든다.** `KG-*`·`MAP-*`의 서버가 준비돼도
화면은 별도 티켓으로 proteinJ에게 남는다 — API를 만든 사람이 화면까지 만들지 않는다.

⚠️ **내 영역 밖의 파일을 고쳐야 하면 먼저 이슈에 코멘트를 남긴다.** 특히
`global/`, `domain/user/`, `domain/dog/`는 세 사람이 공유한다.

## 2. 브랜치 · PR

```
feature/<티켓ID 소문자>-<요약>      예) feature/pn-14-daily-note
```

- **티켓 1개 = 브랜치 1개 = PR 1개.** 여러 티켓을 한 브랜치에 섞지 않는다
- **PR은 작성자 본인이 연다.** 남이 대신 열어주지 않는다. 코드를 쓴 사람이
  무엇을·왜 바꿨는지 가장 잘 안다
- PR 제목은 `[티켓ID] 요약`, 본문에 `Closes #<이슈번호>`를 넣는다
- `main`은 보호돼 있어 **직접 푸시할 수 없다.** 반드시 PR로 들어온다
- 리뷰어는 그 영역의 담당자. 공유 파일(`global/` 등)을 건드렸으면 **proteinJ를 반드시 포함**한다

### PR을 오래 묵히지 않는다

13,000줄짜리 PR은 아무도 제대로 못 읽는다. 화면/기능 단위로 끊어서 올린다.
브랜치가 일주일 넘게 살아 있으면 그 자체가 신호다.

## 3. 절대 겹치면 안 되는 것 — Flyway 마이그레이션

**적용된 마이그레이션 파일은 체크섬 검증 때문에 주석 한 글자도 못 고친다.**
번호가 겹치면 되돌리는 데 큰 비용이 든다.

| 번호 | 선점자 | 용도 |
|---|---|---|
| V1~V5 | Phase 1 (main) | |
| V6~V9 | `feature/partner-reservation` (sechanjang) | 점주 도메인. #70 으로 분리돼 올라와 있다 |
| **V10~** | **다음 사람. 쓰기 전에 이 표를 갱신하는 PR을 먼저 올린다** | |

### 번호는 파일을 쓰기 직전에 잡는다 — 미리 쟁여 두지 않는다

Flyway 는 번호 순서대로만 적용한다(`out-of-order` 기본값 `false`). 번호만 잡아 두고
파일을 안 만들면 이렇게 된다.

```
A 가 V10 을 표에만 적어 둔다 (파일 없음)
B 가 V11 을 만들어 머지 → 각자 DB에 V11 까지 적용됨
A 가 뒤늦게 V10 파일을 추가 → Flyway 가 거부한다. 서버가 안 뜬다
```

**쟁여 둔 번호가 사고를 만든다.** 그 마이그레이션을 쓰는 브랜치를 실제로 시작할 때
잡고, 잡았으면 그 PR 안에서 파일까지 끝낸다.

### 유치원(`KG-*`·`MAP-*`) 쪽 조사 결과

`KG-05`~`KG-14` 는 V6~V9 가 만든 테이블만 읽고 쓰므로 **새 마이그레이션이 필요 없다.**
새 테이블이 필요한 것은 아래 둘뿐인데, 둘 다 선행 결정 대기 중이라 지금 번호를 잡지 않는다.

| 티켓 | 필요한 것 | 막고 있는 것 |
|---|---|---|
| `MAP-04` 상담 기록 | `consultation_notes` | `UD-A` 미결 (8절) |
| `KG-15` 알림 센터 | 알림 수신 설정 | APNs `.p8` 미발급 (7절) |

`MAP-03`(비교 목록)은 서버 저장이 필요한지 자체가 미정이다.

새 마이그레이션이 필요하면:
1. 이 표에서 다음 번호를 확인한다
2. **이 표에 자기 번호를 적는 커밋을 먼저 푸시한다** (선점)
3. 그다음 마이그레이션을 작성한다

번호를 미리 못 박으면 두 사람이 같은 날 같은 번호를 쓴다.

## 4. 상태는 이슈에만 적는다

| 무엇 | 정본 | 고치는 법 |
|---|---|---|
| 티켓 정의·근거·주의사항 | `docs/TICKETS.md` | 손으로 |
| **진행 상태** | **GitHub 이슈** | 이슈를 닫거나 라벨 변경 |
| `docs/STATUS.md` | 없음 — 이슈에서 **자동 생성** | 손대지 말 것 |

- 상태를 문서에 손으로 적지 않는다. 3인이면 반드시 어긋난다
- `STATUS.md`를 직접 편집한 PR은 반려한다. `/tickets-sync`가 덮어쓴다
- 작업을 시작하면 이슈에 **자기를 assignee로 걸고** `status:in-progress` 라벨을 붙인다
- 끝나면 PR의 `Closes #N`으로 자동으로 닫히게 한다

## 5. Claude를 쓸 때 (3인 전원 해당)

세 사람이 각자 Claude로 작업한다. 사람보다 **훨씬 넓게 파일을 건드리기 때문에**
아래를 지키지 않으면 충돌이 폭발한다.

### 반드시

- **작업 범위를 티켓 하나로 좁혀서 지시한다.** "이거 하는 김에 저것도 정리해줘"가
  남의 파일을 건드리는 가장 흔한 경로다
- **커밋 전에 `git status`와 `git diff --stat`을 직접 확인한다.** 의도하지 않은 파일이
  섞였으면 뺀다. Claude는 요청 범위 밖을 고쳐놓고도 잘 설명하지 않을 수 있다
- **공유 문서(`TICKETS.md`, `API_SPEC.md`, `openapi.yaml`)를 통째로 재작성시키지 않는다.**
  필요한 절만 고치게 한다. 전체 재생성은 남의 변경을 조용히 지운다
- **포맷터·import 정리·리네임을 무관한 파일에 퍼뜨리지 않는다.** 진짜 변경이
  대량의 노이즈에 묻혀 리뷰가 불가능해진다

### 하지 않는다

- 이미 적용된 마이그레이션 파일 수정 (3절)
- `STATUS.md` 직접 편집 (4절)
- `.claude/settings.local.json` 커밋 — 개인 설정이다. `.gitignore` 대상
- 남의 영역 파일을 "겸사겸사" 리팩터링
- 빌드가 깨진 채로 커밋. **`./gradlew compileJava`는 최소한 통과시키고 올린다**

### 공유 스킬

`.claude/skills/`에 들어간 스킬은 **팀 공용**이다. 고치면 모두에게 영향이 가므로
PR로 올린다. 개인 설정은 `.claude/settings.local.json`에 두고 커밋하지 않는다.

## 8. 막혔을 때

- **설계 판단이 필요한 것**은 코드로 밀어붙이지 말고 이슈에 적는다.
  `TICKETS.md`의 `O1`~`O7`, 요구사항서의 `UD-A`~`UD-G`가 그런 항목이다
- **`UD-A` 절반 결정됨 (2026-09-09)** — 유치원은 **독립 탭이 아니다.**
  - 유치원을 **다니는** 화면(`C-09`~`C-15`, `KG-09`~`KG-15`)은 **마이 탭 하위**다.
    재원 중인 사람만 쓰는 화면이라 탭으로 빼면 대부분의 사용자에게 평생 빈 탭이 하나 는다.
    견주 앱 화면과 API 계약은 이미 나와 있다 — `API_SPEC.md` 13절, iOS `Features/Kindergarten/`
  - 유치원을 **찾는** 화면(`C-01`~`C-04`, `MAP-*`)이 어디로 들어갈지는 **아직 미결이다.**
    지도를 탭으로 세울지, 친구 탭 안에 둘지가 남아 있다. `MAP-*` 화면 착수 전에 정한다
